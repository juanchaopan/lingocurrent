## REQ-001 响应式英文界面

- 优先级：MVP；状态：有效；来源：初始描述。
- 用户故事：作为学习者，我想在电脑、平板和手机上使用同一套英文界面。
- 验收标准：
  1. Given 使用电脑、平板或手机，When 浏览文章、词卡或复习，Then 页面适配当前屏幕，长句可换行且保留句子单元。
  2. Given 查看界面，When 出现菜单、按钮、状态和错误提示，Then 文案为英文；中文词义及题目内容正常保留。

## REQ-003 资源频道独立调度

- 优先级：MVP；状态：有效；来源：第二轮、第八轮、最终核对补充（覆盖原全站统一时间表）。
- 用户故事：作为学习者，我想每天分时收到新的英文新闻或文章。
- 验收标准：
  1. Given 资源频道配置了自己的时间表，When 到达该频道的执行时间，Then 采集该频道，不要求其他频道使用相同时间表。
  2. Given 后续加入新频道，When 配置其独立时间表，Then 不需改变已有频道的时间安排。
- 业务规则：每个频道定义自己的时区、多个采集时点，以及各时点的篇数。频道配置、时间计划和每次采集运行记录持久化到数据库，实际结构留 Design。
- 架构阶段已确认：使用数据库临时任务表，不使用 Vercel Queue。文章与生成任务同事务保存；任务成功后与文章就绪状态一起提交删除，任务表只留未完成项。采集运行记录和用量记录按各自需求独立保存，不是完成任务归档。
- 示例：America/Toronto 的 00:00、06:00、12:00、18:00，每次 4 篇；新增频道独立配置，不把全站固定为每日 16 篇。不同内容 URL/RSS 分为独立频道，并可归属同一来源分组，如 Yahoo 科技与娱乐。
- 已接受补足：重试去重、失败下批优先重试、来源不足时不以重复文章补数，见 D-013。Yahoo 仍是示例，正式来源在接入前确认。

## REQ-004 正文与来源信息

- 优先级：MVP；状态：有效；来源：初始描述。
- 用户故事：作为学习者，我想读到干净正文，并知道文章来自哪里及何时采集。
- 验收标准：
  1. Given 采集成功，When 保存文章，Then 保存正文、来源、类别和采集时间，不采集正文图片。
  2. Given 阅读文章，When 展示内容，Then 保留原段落顺序与句子内容，并能查看来源信息。
  3. Given 清理器选中当前文章朗读音频，When 提交淘汰，Then 同一数据库事务删除对应文章、正文/句子/时间轴、音频引用及访问记录；提交后对象删除失败可重试，不留下文章供用户继续查询，也不影响个人学习文本/进度。
  4. Given 例句音频缓存已淘汰，When 用户再次点击该例句朗读，Then 例句表行及学习状态仍在，按原例句内容重新生成并缓存音频；不重建已淘汰文章。
- 架构最终确认规则：Neon Object Storage 缓存文章和例句朗读音频，按对象首次创建时间 FIFO；95% 触发清至低于 90%，所有新增音频路径均检查。淘汰文章当前必需音频时，必须同时删除文章、正文/句子/时间轴、专属资产引用及访问历史；不留下文章等待重新生成朗读。例句只清音频及引用，例句仍保存在表里，下次点击朗读时重新生成缓存音频。全部查词缓存文本、词卡、例句文本和复习进度保留。文章删除/访问记录/引用失效在同一 DB 事务提交，外部对象按持久清理状态幂等删除，不声称 SQL/S3 跨系统原子。见 ADR-0005/0007/0015。

## REQ-013 规范词形与词义复用

- 优先级：MVP；状态：有效；来源：初始描述、第五轮。
- 用户故事：作为学习者，我想看懂词在当前句子中的意思，并自动获得可收藏的规范形式。
- 验收标准：
  1. Given 选中原句中的变形单词或短语，When 请求 AI 解释，Then 提供原始选中形式与句子，返回规范词形、词性、语境中文解释和一个例句；查词标题使用规范词形。
  2. Given 个人词库已有同一词的词义和词性，When 解释新语境，Then 将仍有效的已有词义一并提供给 AI，匹配相同含义时复用，避免“声音／声响”仅因译法不同被建为两个词义。
- 业务规则：允许新词义；名词单数、动词原形及特殊形式由 AI 判断，不要求用户手动配置。已删除词义不得传入。

## REQ-014 个人解释持久化与刷新

- 优先级：MVP；状态：有效；来源：初始描述、第四轮、最终核对明确澄清。
- 用户故事：作为学习者，我想刷新不满意的解释和例句，并决定何时收藏。
- 验收标准：
  1. Given 打开查词浮层，When 点击刷新，Then 固定当前词义并生成新例句及目标位置，成功后更新该用户解释缓存，不自动修改或加入生词本；失败保留原数据。
  2. Given 用户 A 刷新了例句，When 用户 B 查同一词，Then B 的个人解释不被 A 的操作覆盖。
  3. Given 当前用户已查过同一上下文中的同一词，When 再次点词，Then 直接显示已缓存的含义和例句，不重复调用 AI；主动刷新才重新生成并覆盖该缓存。
  4. Given 用户删除了对应生词卡，When 在同一文章、同一句中再次点同一个词，Then 查词缓存仍存在并继续复用，不因删除词卡失效。
- 业务规则：解释缓存与生词本独立；在文章、词卡例句及其他可查词上下文均采用这一原则。缓存未命中的新上下文调用 AI；新调用只提供仍存在的个人词库词义，不提供已删词卡词义。
- 业务规则：特别是已匹配个人词库词义时，刷新不能切换词义。解释缓存与已收藏复习词卡互不自动联动，详见 [刷新规则](refresh-behavior-proposal.md)。

## REQ-015 嵌套解释与全场景复用

- 优先级：MVP；状态：有效；来源：初始描述、第七轮。
- 用户故事：作为学习者，我想在文章、词卡详情和复习中，用相同方式继续查例句里的词。
- 验收标准：
  1. Given 文章、词卡或复习的例句可见，When 点击或拖选可见词语，Then 可打开解释并收藏；浮层例句仍支持继续查词，形成多层。
  2. Given 已打开多层浮层，When 点击屏幕空白处，Then 只返回上一层。
- 业务规则：文章朗读时打开查词浮层仍继续播放；播放例句才暂停文章，不同时播放两段声音。

## REQ-016 目标词位置、高亮和隐藏边界

- 优先级：MVP；状态：有效；来源：第五轮、第八轮。
- 用户故事：作为学习者，我想在解释时看清目标词，在练习时不被泄露答案。
- 验收标准：
  1. Given AI 返回例句，When 保存并显示，Then 同时获得目标词实际位置，解释卡高亮该位置；目标的屈折形式也能定位。
  2. Given Speak 或 Spell 正在答题，When 展示例句，Then 目标词隐藏、不可点击，也不能从其前方拖选到其后方而跨过或包含它；其他可见词仍可查阅和收藏。
- 已接受补足（原来源为 AI）：Speak / Spell 作答前不提供会读出隐藏答案的完整例句朗读；目标位置和生成选项须校验有效，失败不覆盖旧内容，见 D-006、E-003。

## REQ-017 收藏、快照与重复替换确认

- 优先级：MVP；状态：有效；来源：初始描述、第四至第五轮。
- 用户故事：作为学习者，我想收藏当前满意的中文解释和例句，并区分同词不同义。
- 验收标准：
  1. Given 点击例句后的加号，When 该用户没有同词同义条目，Then 收藏规范词/短语、词性、词义、中文解释及当前例句；不同词义建立独立词条。
  2. Given 已有同词同义条目，When 再次收藏，Then 先提示是否替换；确认后替换中文解释和例句，保留三个模式的全部进度；取消则不修改旧条目。
- 业务规则：收藏后内容独立于原浮层后续刷新，不自动跟随其变化。

## REQ-018 收藏时生成四个翻译选项

- 优先级：MVP；状态：有效；来源：初始描述、第四轮。
- 用户故事：作为学习者，我想第一次 Translate 复习时就有可用题目。
- 验收标准：
  1. Given 新词条正在加入生词本，When 保存完成，Then 已生成并保存四个翻译选项，每项包含词性和中文，其中一个匹配当前词义。
  2. Given 刚查词但尚未收藏，When 展示解释，Then 不为此操作单独生成 Translate 选项。
- 边界：重复替换后的题目一致性与生成失败处理见 D-007，不允许题目正确答案仍指向已被替换的含义。
- 业务规则：四选项在加入生词本时生成；未收藏的解释卡刷新不提前生成。词义固定、仅换例句时复用已有选项。确需同步重建选项时可合并一次请求，验证完整后一起保存，失败不修改旧卡或进度。

## REQ-019 生词列表、到期数及 Archive

- 优先级：MVP；状态：有效；来源：初始描述。
- 用户故事：作为学习者，我想优先看到最需要复习的词，并知道三个模式的状态。
- 验收标准：
  1. Given 打开个人生词列表，When 排序和渲染，Then 更紧迫的到期条目靠前；每条显示 Speak、Spell、Translate 三个状态，区分新词、剩余时间、已到期和已完成，并使用不同颜色。
  2. Given 某条目三个模式全部完成，When 保存最后一次成绩，Then 条目进入 Archive；任一模式未完成时仍留在活动词库。
- 业务规则：三个入口各显示 due/new 数量；已到期短练计入对应模式 due。列表以三个未完成模式中最早到期时间排序，新词单独标记，见 D-008。

## REQ-020 词卡详情与固定词义换例句

- 优先级：MVP；状态：有效；来源：初始描述、第五至第七轮。
- 用户故事：作为学习者，我想查看词卡并更换例句，同时继续练习同一个词义。
- 验收标准：
  1. Given 打开词卡详情，When 展示内容，Then 显示规范词形、中文解释及一个例句，例句可朗读、高亮、查词和收藏。
  2. Given 点击详情中的换例句按钮，When 生成成功，Then 用新例句替换当前例句但保持原词义和复习进度，返回新的目标位置。
- 业务规则：词义不变则复用四选项；不反向覆盖文章中的解释缓存。生成失败保留旧例句、选项和进度。

## REQ-021 删除词卡及禁止单模式重置

- 优先级：MVP；状态：有效；来源：第六至第八轮。
- 用户故事：作为学习者，我想删除不再需要的词卡，而不是单独重置某种复习成绩。
- 验收标准：
  1. Given 删除个人词卡，When 删除完成，Then 该词卡及其全部复习记录被删除，不再提供其已删词义给 AI，也不再参与用户的复习。
  2. Given 用户之后再次点该词，When 当前上下文已有解释缓存，Then 继续显示缓存；缓存未命中或主动刷新时才调用 AI，且不把已删生词卡的词义作为词库上下文传入。
- 业务规则：删除词卡、关联题目及全部复习记录并移出当前队列，不删除独立解释缓存。重新收藏建立新词卡，三个模式均未开始。不提供单模式重置；Archive 可查看和删除，不设恢复进度入口。同词其他词义和其他用户不受影响。

## REQ-022 三个独立复习入口

- 优先级：MVP；状态：有效；来源：初始描述、第五至第六轮。
- 用户故事：作为学习者，我想分别练习说、拼写和理解中文含义。
- 验收标准：
  1. Given 点击 Speak、Spell 或 Translate，When 开始复习，Then 进入该模式的新词、正式到期词及已到期重练词队列。
  2. Given 提交某模式结果，When 更新日程，Then 只更新这个词条的该模式，其他两种模式不改变。
- 业务规则：提供 Speak、Spell、Translate 三个主按钮，各显示 due/new；All / Due / New 筛选默认 All。先最早到期，再按加入顺序处理新词，无每日额度限制。会话中新收藏词下次启动进入，已到期短练可在当前会话重新入队，见 D-008、REQ-028。

## REQ-023 Speak 语音作答

- 优先级：MVP；状态：有效；来源：初始描述、第三轮、第五至第六轮。
- 用户故事：作为学习者，我想根据中文和语境说出英文目标词。
- 验收标准：
  1. Given Speak 题目，When 开始作答，Then 显示中文、词性和隐藏目标词的例句，以录音提交规范词形或短语。
  2. Given 获取有效录音，When 判断匹配，Then 先验证本地识别/判定方案，效果不足时允许 OpenAI 根据原始录音与目标词判定；内部结果为正确或错误。
- 边界：不能仅凭转写字符串相等宣称判音可靠；录音权限、音频无效或服务故障应可重试且不计答错。
- 最新明确要求：这里的原始录音指 Speak 作答时用户录下的声音，不需要长期保留；不因此删除文章/例句的 TTS 音频。
- 架构访谈补充（2026-11-15，用户直接修正）：不测浏览器本地模型；本地识别/匹配限定 Vercel 服务端，不适用时走 OpenAI。用户允许返回多个识别候选、目标出现在前 K 项时通过；引擎、K 及得分含义尚待选定和 staging 验证。这是词语匹配候选规则，不将未经实测的识别结果宣称为可靠发音评分。

## REQ-026 已完成轮次与间隔常量表

- 优先级：MVP；状态：有效；来源：初始描述、第五轮、最终核对补充。
- 用户故事：作为学习者，我想让三种能力分别按逐渐增长的间隔复习。
- 验收标准：
  1. Given 某词条的某个复习模式，When 完成首次正式复习，Then 已完成轮次记录为 1；完成第二轮记录为 2，三种模式各自独立。
  2. Given 当前已完成轮次确定，When 计算下一次正式复习，Then 查统一常量表中相邻轮次的等待天数，从实际完成时间计算，间隔不按词条分别硬编码。
- 业务规则：已选间隔为 1、2、4、7、15、30 天；错后短练成功保留原轮次，重新等待该节点原间隔，见 REQ-027。
- 业务规则：初始未开始轮次记为 0；完成所有约定间隔后，该模式完成。最终完成轮次由统一常量表的终点定义，表的键、索引和终点在 Design 明确，不将“七次/59 天”的早期推算硬编码为另一套独立规则。表须完整体现已选的六个等待间隔，不因错后重练增加完成轮次。

## REQ-027 错后十分钟重练且保留阶段

- 优先级：MVP；状态：有效；来源：第五至第六轮。

- 验收标准：
  1. Given 当前阶段间隔为 2 天，When 正式复习答错，Then 立即显示正确答案，安排 10 分钟后重练；再错则从本次错误再等 10 分钟。
  2. Given 该词重练答对，When 重新排期，Then 保持当前 2 天阶段，从本次答对重新等 2 天；之后正式到期答对才推进到 4 天。
- 业务规则：各阶段同理，包括最后阶段；故障不当作学习者答错。10 分钟为用户产品选择，不是科学最优性承诺。

## REQ-031 规模与费用目标

- 优先级：MVP；状态：有效；来源：第七至第八轮（预算口径以第八轮为准）。
- 用户故事：作为维护者，我想支撑预计受邀规模，并尽量保持低费用。
- 验收标准：
  1. Given 设计与 staging 验证，When 评估容量，Then 以一年内 1,000 个账号、100 人同时使用为目标，说明验证的使用配比和瓶颈，不能把页面并发等同于语音模型并发。
  2. Given 月度总费用超过 30 美元期望，When 用户继续使用，Then 不因该金额自动禁止任何用户调用或停用功能；费用/用量相关信息按 REQ-034 入库，不增加费用看板。
- 业务规则：30 美元是期望，不是硬上限或用户额度；不得添加按此金额的停用策略。没有硬上线期限。初始性能目标：正常网络下列表/已生成正文 P95 3 秒内可读，AI 查词/语音判定 P95 10 秒内返回；在 staging 测量，不为性能开 spike，未测不作达标承诺。
- 架构访谈补充：上述总费用期望不取消 Vercel 零部署支出约束；最新用户明确 Neon 数据库也只用 Free，接受有限历史恢复/单手动快照的弱恢复保障，不把初期 24 小时 RPO/RTO 写成保证。音频按对象创建时间 FIFO、95%/90%，包含文章及例句；文章淘汰删访问记录，所有个人学习文本与进度保留，见 REQ-004/Q-034。计算、出网、请求及数据库增长仍可能触及免费硬配额；不自动升级，不声称删除音频能返还历史用量。
