## REQ-003 资源频道独立调度

- 优先级：MVP；状态：有效；来源：第二轮、第八轮、最终核对补充（覆盖原全站统一时间表）。
- 用户故事：作为学习者，我想每天分时收到新的英文新闻或文章。
- 验收标准：
  1. Given 资源频道配置了自己的时间表，When 到达该频道的执行时间，Then 采集该频道，不要求其他频道使用相同时间表。
  2. Given 后续加入新频道，When 配置其独立时间表，Then 不需改变已有频道的时间安排。
- 业务规则（2026-11-16用户澄清原意）：Source、Channel及其时区/采集时点/篇数是相对稳定的数据库配置。到点建立该Channel的一次临时采集任务，可含多篇文章的临时明细；完成后删除父任务和全部明细，不保留永久运行记录或完成任务归档。此前将运行记录理解为永久历史是AI解释偏差，本条恢复用户原意。
- 使用同一数据库临时任务表，不使用 Vercel Queue。到点建频道任务与推进计划next_run_at同事务；正文/句子、逐篇检查点及文章音频任务同事务保存。采集完成并交接音频任务后删除频道任务/明细；音频任务在完整音频/时间轴发布的事务中删除。失败未完成项保留重试；独立用量记录只记录模型调用用量，不复制采集历史。
- 示例：America/Toronto 的 00:00、06:00、12:00、18:00，每次 4 篇；新增频道独立配置，不把全站固定为每日 16 篇。不同内容 URL/RSS 分为独立频道，并可归属同一来源分组，如 Yahoo 科技与娱乐。
- 已接受补足：重试去重、失败下批优先重试、来源不足时不以重复文章补数，见 D-013。Yahoo 仍是示例，正式来源在接入前确认。

## REQ-004 正文与来源信息

- 优先级：MVP；状态：有效；来源：初始描述。
- 用户故事：作为学习者，我想读到干净正文，并知道文章来自哪里及何时采集。
- 验收标准：
  1. Given 采集成功，When 保存文章，Then 保存正文、来源、类别和采集时间，不采集正文图片。
  2. Given 阅读文章，When 展示内容，Then 保留原段落顺序与句子内容，并能查看来源信息。
  3. Given 清理器选中当前文章朗读音频，When 提交淘汰，Then 同一数据库事务删除对应文章、正文/句子/时间轴、音频引用及访问记录；提交后对象删除失败可重试，不留下文章供用户继续查询，也不影响个人学习文本/进度。
  4. Given 例句音频缓存已淘汰，When 用户再次点击该例句朗读，Then 例句表行及学习状态仍在，按原例句内容重新生成并缓存音频；不重建已淘汰文章。
- 架构最终确认规则：Neon Object Storage 缓存文章和例句朗读音频，按对象首次创建时间 FIFO；95% 触发清至低于 90%，所有新增音频路径均检查。淘汰文章当前必需音频时，必须同时删除文章、正文/句子/时间轴、专属资产引用及访问历史；不留下文章等待重新生成朗读。例句只清音频及引用，例句仍保存在表里，下次点击朗读时重新生成缓存音频。全部查词缓存文本、词卡、例句文本和复习进度保留。文章删除/访问记录/引用失效在同一 DB 事务提交，外部对象按持久清理状态幂等删除，不声称 SQL/S3 跨系统原子。见 ADR-0005/0007/0015。

## REQ-011 跨文章连续播放和句子同步

- 优先级：MVP；状态：有效；来源：初始描述。
- 用户故事：作为学习者，我想从列表第一篇开始连续听文章，并跟随当前句。
- 验收标准：
  1. Given 启动列表Play all，When 开始或当前文章结束，Then 进入首篇首句；篇末先回保存的列表上下文，再自动进入固定队列下一篇首句，不要求用户再次点击（2026-11-16用户修订）。
  2. Given 当前播放进入另一文章或句子，When 位置更新，Then 自动进入对应文章、滚动到对应句并高亮。
  3. Given 当前文章是当前列表页最后一篇，When 播放结束且固定队列仍有下一篇，Then 先回到下一页列表，再自动进入该页第一篇首句；触控确保下一批已加载。访问更新时间不得重排本次队列；最后一篇结束回列表并停止。
  4. Given 点击某行播放，When 开始，Then 从该文章首句开始，按冻结的当前组合查询顺序连续播放其后文章，跨页规则相同；跳过队列中被删文章，新采文章下次启动纳入（2026-11-16第四轮）。
- 业务规则：保存足以支持单句播放、进度定位和同步的句子时间映射；“lyrics”采用同步时间轴含义，不另要求字幕文件导出（D-011）。

## REQ-013 规范词形与词义复用

2026-11-16用户数据模型修订：相同用户在相同规范句子选中相同范围时，无论来自文章或例句均复用同一解释缓存。Lookup合并句子/选区/词义，Lookup的examples以lookup_entry_id关联；词卡保存收藏原句及范围，并拥有独立vocabulary_examples，以vocabulary_card_id关联，一对多；不设current_example_id。文章/解释/词卡/题组/复习不设业务版本字段或lexeme辅助表；并发由应用服务重查、事务锁/唯一约束和通用operationId去重保护。刷新仍互不自动覆盖，删除词卡仍保留Lookup缓存。

- 优先级：MVP；状态：有效；来源：初始描述、第五轮。
- 用户故事：作为学习者，我想看懂词在当前句子中的意思，并自动获得可收藏的规范形式。
- 验收标准：
  1. Given 选中原句中的变形单词或短语，When 请求 AI 解释，Then 提供原始选中形式与句子，返回规范词形、词性、语境中文解释和例句集合（首次可仅一个）；查词标题使用规范词形。
  2. Given 个人词库已有同一词的词义和词性，When 解释新语境，Then 将仍有效的已有词义一并提供给 AI，匹配相同含义时复用，避免“声音／声响”仅因译法不同被建为两个词义。
- 业务规则：允许新词义；名词单数、动词原形及特殊形式由 AI 判断，不要求用户手动配置。已删除词义不得传入。

## REQ-014 个人解释持久化与刷新

- 优先级：MVP；状态：有效；来源：初始描述、第四轮、最终核对明确澄清。
- 用户故事：作为学习者，我想刷新不满意的解释和例句，并决定何时收藏。
- 验收标准：
  1. Given 打开查词浮层，When 点击刷新，Then 固定当前词义并生成新例句及目标位置，成功后更新该用户解释缓存，不自动修改或加入生词本；失败保留原数据。
  2. Given 用户 A 刷新了例句，When 用户 B 查同一词，Then B 的个人解释不被 A 的操作覆盖。
  3. Given 当前用户已查过同一上下文中的同一词，When 再次点词，Then 直接显示已缓存的含义和例句，不重复调用 AI；主动刷新才重新生成并覆盖该缓存。
  4. Given 用户删除了对应生词卡，When 在同一文章、同一句中再次点同一个词，Then 查词缓存仍存在并继续复用，不因删除词卡失效。
- 业务规则：解释缓存与生词本独立；在文章、词卡例句及其他可查词上下文均采用这一原则。缓存未命中的新上下文调用 AI；新调用只提供仍存在的个人词库词义，不提供已删词卡词义。
- 业务规则：特别是已匹配个人词库词义时，刷新不能切换词义。解释缓存与已收藏复习词卡互不自动联动，详见 [刷新规则](refresh-behavior-proposal.md)。

## REQ-015 嵌套解释与全场景复用

- 优先级：MVP；状态：有效；来源：初始描述、第七轮。
- 用户故事：作为学习者，我想在文章、词卡详情和复习中，用相同方式继续查例句里的词。
- 验收标准：
  1. Given 文章、词卡或复习的例句可见，When 点击或拖选可见词语，Then 可打开解释并收藏；浮层例句仍支持继续查词，形成多层。
  2. Given 已打开多层浮层，When 点击屏幕空白处，Then 只返回上一层。
- 业务规则：文章朗读时打开查词浮层仍继续播放；播放例句才暂停文章，不同时播放两段声音。

## REQ-016 目标词位置、高亮和隐藏边界

- 优先级：MVP；状态：有效；来源：第五轮、第八轮。
- 用户故事：作为学习者，我想在解释时看清目标词，在练习时不被泄露答案。
- 验收标准：
