# 全文 RSS 与多话题频道 Spike 计划

日期：2026-11-16（America/Toronto）。状态：**仅记录，等待 Roadmap 创建 type:spike Issue；当前不执行调查或探针**。用户明确澄清“不是让你现在做，是先记一下，后面Roadmap会列出这个Spike任务在Issues里面的”。本计划不是研究结果，也不代表批准任何来源接入。

## 要回答的问题

哪些英文站点在 RSS/Atom 中直接提供完整正文，并提供可独立配置的科技、时尚及其他话题频道，适合本项目按频道URL采集而无需网页scraping？

## Issue 范围与验收

- 由Roadmap创建独立type:spike Issue，排在正式来源/频道接入实现前；不与TTS/Speak两个Spike合并。
- 查明官方feed入口、站点来源名/图标、话题名与每个话题的独立feed URL；不同站点不一定有相同频道集合，不能由科技URL猜测时尚URL存在。
- 对每个候选feed抽取至少3篇（少于3篇则标样本不足），比较feed正文字段与文章正文，排除摘要、read more截断、正文实际另需请求/付费才能取得的情况；不能只用word数阈值判断全文。
- 记录更新频率/文章长度/英语适配、稳定GUID/链接去重、HTML清理和来源条件。区分“技术上有全文”和“允许存储全文/生成TTS”；不把RSS可订阅等同于再分发授权。
- 输出候选矩阵、实际feed URL、检查时间/样本数/结果/限制和推荐频道配置草案，供用户选择。Yahoo仍为UI示例，不预设其能通过全文验证。
- 同一来源可配置多个channels，各有category、feed_url、时区和独立计划；通用feed新增频道无需改代码。优先选直接全文的feed，无法满足时如实列缺口，不偷偷引入scraping代替。

执行Issue时再设时间盒与候选数量。当前不抓取正文、不执行探针、不创建Issue、不修改云资源或批准来源清单。已发生的初步检索不计作Spike证据/结果。
