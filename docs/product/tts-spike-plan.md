# TTS 试听 spike 计划

来源：用户明确将朗读 demo 放入 TTS spike，并在架构阶段另外确认 Speak 候选也独立 spike，见 speak-spike-plan.md。本文只覆盖 TTS；完整集成和 D-014 仍在 staging，不增加独立全站性能 spike。

状态：计划随 kickoff 于 2026-11-15 最终确认，尚未执行。实际样音与音色选择是后续产出，不以计划确认冒充实测。

## 问题与用户决定

架构阶段后续研究建议见 [语音候选次序](../architecture/speech-candidates.md)：以当前 OpenAI 音频路线作质量参照，再比较 Kokoro-82M 与 Supertonic 3；顺序由 AI 应用户要求推荐，最终引擎/音色尚未选择，尚未生成样音。首轮仍遵守下方 3–4 段同文 demo、最多三种方案及时间盒，不直接锁定已公布关闭日期的旧 Speech API 模型。

- 问题：哪些自然 TTS 方案与音色适合长期听英文文章？
- 产出：几段可播放、可直接比较的 demo，由用户实际试听并选择。
- 当前尚未运行，尚无本项目生成的试听音频；不把官方演示或文档说明冒充本项目实测。
- 各环境仍使用同一个 OpenAI key；仅云端 AI 调用使用 OpenAI，不排除符合部署要求的本地 TTS 候选。
- 计算部署仍受 Vercel 约束，开发环境能生成样音不代表已经证明正式部署适用。

## 起始执行范围（AI 建议，用户默认）

- 首轮 3–4 段 demo，用相同的一段英文，覆盖长短句、数字和缩写，便于比较。
- 优先覆盖至少两种 TTS 方案，再比较有希望方案的不同音色；标注模型、音色、语速及参数。
- 附试听音频、文本和最基本的生成用量记录，用户按自然度、清晰度和长时间收听舒适度选择，不先强制量化评分。
- 起始时间盒最多两小时、两轮试听，按计划记录执行结果；到时尚无结论如实报告，不无限扩展。
- 只做试听和必要的音频生成可行性检查，不构建完整网站或 D-014 性能探针。
- 架构阶段用户补充：音频适度压缩，不追求高保真，优先读词清楚、自然。比较低码率/单声道听感、编码耗时和实际文件大小；最终编码与码率由证据决定，不把某个压缩率当已确认质量。输出会进入 Neon Object Storage，例句也作为按需可淘汰缓存。

## 实际执行约定

进入实际 spike 时按 spike 技能创建隔离的 `spike/` 分支、`spikes/` 目录及具体 `SPIKE.md`，记录问题、已确认判据、运行方式与结果。当前只有产品阶段计划，没有创建探针代码或发起付费调用。选型结论记录后再用于正式设计；示例代码不直接作为正式实现。
