## 要回答的问题

在实际 Vercel Hobby 中，候选识别库能否部署、在资源和月度免费额度内运行，并按目标词/短语与识别前 K 候选进行可接受的匹配？不适用时，用 OpenAI 原始录音判定能否满足效果与成本要求？

## 已知平台基线与须实查的项目

[Vercel CPU/内存说明](https://vercel.com/docs/functions/configuring-functions/memory)当前列 Hobby 为 2 GB/1 vCPU；[函数限制](https://vercel.com/docs/functions/limitations)列单次最长 300 秒、普通 Node 包 250 MB/Python 包 500 MB，另有 large functions Beta 路线。不能只测开发机或只查看模型 ZIP 大小。

spike 需记录：实际账号套餐、Fluid Compute、区域、运行时及 CPU 架构、函数配置、包体解压大小、可用原生库、内存峰值、临时空间、冷/热启动行为。CPU 品牌和长期硬件一致性不是已知承诺；按 CPU 路线验证，不假设可获得 GPU。Beta 大包是否可用以实际部署为准，不能用大包能力代替 2 GB 内存与 CPU 预算检查。

权重随函数部署或使用验证过的临时下载方式；不占文章朗读专用 Blob。临时缓存可能随实例回收消失，不能假设只下载或加载一次。

## 顺序

1. 按 [候选研究次序](../architecture/speech-candidates.md)先筛 Vosk 英语 lgraph/小模型及对应运行库的包体、许可、内存与实际部署。如果静态限制已不满足，记录证据后跳过，不为其增设计算服务器。
2. 对可部署候选，在真实 Hobby 函数执行录音识别、候选排序和服务端目标匹配，区分音频解码、模型加载与推理耗时。
3. 用同一人工标注录音与 OpenAI 原始音频判定作必要对照；人工标签是真值，OpenAI 不是自动正确答案。
4. 当前路线不能满足时记录否决原因和后备建议；PocketSphinx 仅按需继续，不无限扩展候选。

## 样本与结果

沿用已接受的起始样本：本人 10 条正确、10 条错误、至少 3 条无效录音，包含近音词、低频词、短语、静音/噪声/截断；相同录音换错误目标做负对照。浏览器仅录音，不测浏览器本地模型。

报告误接受、误拒绝、无效录音处理，以及各 K 下的匹配结果；不先把 K 锁为某个默认常量，也不把 N-best 路径得分当百分比正确概率。目标不能是解码器唯一允许输出，否则无法检验误接受。

冷/热请求要重复观察，报告样本数、耗时分布和内存，不用一次成功代表可靠。原始录音只用于本次经授权测试和必要云端对照，不长期保留。

## 免费容量判据

[Hobby 配额](https://vercel.com/docs/plans/hobby)当前包括 4 active CPU 小时、360 GB·小时内存及 100 万次函数调用/月。记录函数内 CPU 时间与平台 Usage 观测；二者口径/延迟不同，不能把本地 wall time 直接当平台 CPU 计量。

按 30,000 次 Speak/月参考量外推，分别列冷启动占比、音频长度、实例复用和其他网站/TTS 工作的假设。若全部 4 小时都给 Speak，也仅平均 0.48 CPU 秒/次；必须给其他工作留空间，不能把“单次跑通”判成“目标规模免费可用”。实际资源分配与通过阈值在执行前明确。

最终结论区分：无法部署、可部署但效果不合格、效果可用但免费容量不足、可以在明确参考量下采用、需要 OpenAI 后备。结果未知时保持 ADR 提议，不先选定引擎。
