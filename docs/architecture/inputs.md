# 架构输入与容量测算

日期：2026-11-15（America/Toronto）。架构已获用户最终确认，指标与估算分别标注；见 [overview](overview.md) 及 ADR。语音引擎仍待 spike，不把架构确认视为运行证据。

## 已确认指标

| 指标 | 目标值 | 依据 |
|---|---|---|
| 账号及并发 | 一年内最多 1,000 账号，100 人同时使用；不等同于 100 路同时判音 | REQ-031 |
| 活跃参考量 | 100 日活；每人每天 10 次未命中/刷新查词、10 次 Speak | 架构访谈第一轮用户选择；用于测算，不作为额度 |
| 文章增长参考量 | 全站参考 16 篇/天，每篇约 800 英文词，5,840 篇/年 | 架构访谈第一轮用户选择；正式频道仍独立配置，不固定全站配额 |
| 数据保留 | Neon 音频含文章及例句，按对象创建时间 FIFO、95%/90%；个人解释文本/词卡/例句/复习保留。文章淘汰删访问历史，例句音频未命中重建；临时任务成功即删，Speak 原始录音不长期保存 | 最新确认；ADR-0003/0005/0007 |
| 页面性能 | 正常网络下列表/已生成正文 P95 ≤ 3 秒 | REQ-031；D-014，staging 验证，尚无测量 |
| AI 性能 | AI 查词/判音 P95 ≤ 10 秒 | REQ-031；D-014，staging 验证，尚无测量 |
| 可用性 | 月可用性目标 99.5%，非托管商 SLA 承诺 | 架构访谈第一轮用户选择 |
| 灾难恢复 | 坚持 Neon Free，接受有限历史恢复/单手动快照的较弱保障；原先 24 小时 RPO/RTO 不再作为保证，实际恢复需演练 | 最新用户选择；ADR-0013 |
| 一致性 | 个人写操作提交后读到已保存状态；词卡/选项更新原子化，失败保留旧数据；复习重复提交不重复推进，删除后的旧请求不能复活词卡 | REQ-017–REQ-021、REQ-028、REQ-030 |
| 发布一致性 | 正文与完整 TTS/时间轴都已就绪才对用户可见；后台生成允许异步，未完成文章不可进入列表/搜索 | REQ-005、REQ-011、REQ-030 |
| 安全及隐私 | Clerk 邀请制 Google 登录；个人数据按用户隔离；密钥只进入服务端；不长期保存原始作答录音 | REQ-002、REQ-023、REQ-029 |
| 合规边界 | 来源接入前核对正文获取与复用条件；正式来源未确认；地区驻留或特定认证要求尚未指定，不推断为已满足任何认证 | Q-001、content-source-research.md |
| 月成本 | 总月费以 30 美元为优化期望，不按此金额停用；Vercel 与 Neon 坚持免费，不自动升级；用量/费用入库，无费用看板 | REQ-029、REQ-031、REQ-034；最新用户选择 |
| 维护人力 | 用户一人维护，优先减少部署与运维；无指定技术偏好，AI 推荐、用户逐项选择；每周投入时间未提供，不据此承诺交付日期 | 架构访谈第一至三轮用户回答 |
| 平台 | Vercel 网站与计算、Neon 数据库、Clerk 身份；云端 AI 为 OpenAI，本地模型允许但执行方式须符合约束 | REQ-029 |
| 配置 | GitHub Secrets/Variables 管理静态配置；spike、staging、production 等环境共用一个 OpenAI key，仅注入服务端 | REQ-029；Q-020 |

99.5% 在 30 天月份对应约 3.6 小时不可用时间，仅用于解释目标；服务依赖故障仍需计入应用可用性观测。RPO/RTO 不能用“有备份功能”代替实际恢复证明。

## 可复算容量估计

以下为工程估算，不是实测压缩率、语速或费用承诺。月计算使用 30 天，年计算使用 365 天。

| 项目 | 计算与含义 |
|---|---|
| 新文章 | 16 × 30 = 480 篇/月；16 × 365 = 5,840 篇/年 |
| 文章英文词数 | 480 × 800 = 384,000 词/月；5,840 × 800 = 4,672,000 词/年 |
| 文章音频时长 | 暂按 150 词/分钟估算：约 2,560 分钟/月、31,147 分钟/年；实际以所选引擎/音色测量 |
| 文章音频大小 | 暂按 64 kbit/s 单声道估算：约 1.23 GB/月新增、14.95 GB/年新增，十进制 GB；尚未计例句、临时分块、备份或多版本 |
| 查词生成量 | 100 × 10 × 30 = 30,000 次/月；365,000 次/年；缓存命中无需再次生成 |
| Speak 作答量 | 100 × 10 × 30 = 30,000 次/月；365,000 次/年；只评估 Vercel 服务端匹配或 OpenAI，不测浏览器本地模型；云端占比待验证 |
| 解释缓存 | 若每条包含例句、目标位置和上下文的数据平均为 B 字节，则约 365,000 × B 字节/年；索引、行开销和刷新覆盖另计 |
| 生词与复习 | 尚无收藏比例、每用户词数、复习频次数据；Design 按实际字段和参考使用行为补算，不假称每次查词都收藏 |
| 音频出网 | 日活 × 每人每日实际收听分钟 × 60 × 音频 bit/s ÷ 8 × 天数；缓存命中、重复播放和设备行为影响实际账单 |

费用模型：Vercel 计算/调度/分发 + Neon 数据库/对象存储/出网 + Clerk + 文本生成 + 实际云端 Speak + TTS。Vercel 与 Neon 坚持 Free，不自动升级；30 美元总月费仍不作为应用停用阈值。免费硬配额可能暂停服务；语音方案未实测，费用未验证。15 分钟 DB 心跳可能让计算每轮保持活跃约 5 分钟，按 0.25 CU、30 天粗估即约 60 CU 小时/月，另加真实业务与分支活动；不是已测计量。见 [免费可行性调查](free-tier-feasibility.md)。

## 已核对的平台事实

核对日期同上。平台文档是能力与约束证据，不是本项目部署或性能验证结果。

| 事项 | 官方依据 | 对本项目的影响与待决项 |
|---|---|---|
| 新旧调度区别 | [Schedules](https://vercel.com/docs/schedules)、[旧 Cron 费用与限制](https://vercel.com/docs/schedules/cron-jobs/usage-and-pricing) | 旧 Cron 已标为 legacy；新 Schedules 提供时区等能力。不能直接把旧 Cron 的限制套在 Schedules 上。 |
| Schedules Beta | [限制](https://vercel.com/docs/schedules/limits) | Hobby 每 15 分钟可触发、固定 15 分钟抖动窗口、团队每账期最多 5,000 次运行；超量跳过调度。单个心跳每 30 天约 2,880 次，其他环境也消耗团队额度。最新用户要求及时处理，单靠扫描不能保证分钟级发现或续跑。 |
| 调度可靠性 | [Schedules 概念](https://vercel.com/docs/schedules/concepts) | 可能晚到、漏过或重复。直接函数/路径目标失败不自动重试；队列目标依赖队列重投。无论选择什么调度器，频道计划和业务执行状态仍需存数据库并可补偿。 |
| 函数资源边界 | [Functions limits](https://vercel.com/docs/functions/limitations) | 普通 Node 函数包 250 MB、Python 500 MB；Hobby 2 GB 内存/300 秒，Pro 常规最长 800 秒。大型函数/更长时长有 Beta 路线，不预设已可用；本地模型不能仅凭开发机能跑就认定可部署。 |
| 后台队列 | [Vercel Queues](https://vercel.com/docs/queues) | 比较后明确不采用；只用 Neon 临时任务表，成功即删，ADR-0003。 |
| 音频私有存储 | [Neon Object Storage](https://neon.com/docs/storage/overview) | 已选 Neon 私有对象存储，Vercel Blob 仅比较留档；正常集成验证鉴权、Range、分支删除释放与后台播放，ADR-0007。 |
| 部署预算 | [Hobby plan](https://vercel.com/docs/plans/hobby) | 用户第三轮指定 Vercel 支出为 0，Pro 不在当前方案内；免费计算与存储额度不保证覆盖目标规模，见免费可行性调查。 |
| Neon 费用与恢复 | [Neon plans](https://neon.com/docs/introduction/plans) | 坚持 Free，至多 6 小时/1 GB 变更历史及一个手动快照；接受弱恢复，不承诺原 24 小时 RPO/RTO，ADR-0013。 |
| 邀请模式 | [Clerk access control](https://clerk.com/docs/guides/secure/restricting-access) | Clerk 有 Invite-only 模式；Google 登录限制、移除邀请后既有会话处理及服务端数据隔离仍需正式设计与验证。 |

## 访谈进度

- 第一轮：维护人数、可用性/RPO/RTO、内容参考量及活跃参考量已获用户选择。
- 第二轮：用户委托 AI 推荐技术与架构风格，采用模块化单体（ADR-0001）；明确选择 Next.js + TypeScript（ADR-0002）；当时回答采集时间精度不敏感。
- 第三轮：选择 Neon 任务表方向，要求及时唤醒，并询问积压处理；Vercel 支出为 0，不默认升级。Private Blob 为偏好，免费容量冲突待解决。取消浏览器本地识别，只研究 Vercel 服务端匹配/Top-K 或 OpenAI。其他细节逐项询问，不委托 AI 一次决定全部。
- 第四轮：用户要求先设计一致性，允许 15 分钟处理积压，希望在任务表与 Queue 中选一个；已授权按容量自动淘汰最早文章，不再要求所有文章永久保留。要求区分 TTS 与识别并由 AI 推荐候选研究次序。
- 第五轮已确认：仅临时任务表，成功即删；Blob 仅文章朗读，TTS 任务内按 95%/90% 淘汰最早文章并删访问记录，所有个人学习数据及查词缓存保留。TTS/Speak 分别 spike，Speak 必须验证真实 Hobby 适用性。用户另问数据库能否集中在 Vercel，调查见 database-options.md。
- 第六轮：Drizzle、Zod 已选；例句音频也缓存，按对象创建时间 FIFO，命中播放、未命中生成（ADR-0005）。
- 第七轮：Neon Object Storage、Vercel-managed Neon、pnpm、Drizzle schema 生成 SQL 迁移；压缩优先自然清楚（ADR-0007/0008）。
- 第八至后续轮：已选择 TanStack Query、Zustand、Tailwind/令牌、容器/展示分层、原生语义组件、自有样式、AI 设计稿先确认、Storybook、Vitest/RTL、Playwright 功能/截图；四环境及 main 自动 staging/标签后手动生产；HTTP/JSON REST、英文 FTS；免费 OTel 条件核实采用，数据库坚持 Free/弱恢复。ADR-0009–0014。
- 最终审阅：用户明确文章当前音频淘汰须同时删文章；例句只删音频、例句留表、下次点朗读重建，其余方案通过并要求 finalize architecture。已更新 overview、ADR-0005/0015 与产品边界。后续用户澄清顺序：先 Design、scaffold/GitHub，再 roadmap 创建两个 type:spike 任务，按依赖执行，不在架构完成后立即开探针。
- TTS/Speak 分别按已接受计划 spike，Speak 必须测真实 Hobby；完整集成、手机行为与 D-014 留 staging，不另加全站性能 spike。
