# 恢复频道采集任务完成即删的原意

日期：2026-11-16。状态：用户直接纠正，规格已修正；Design整体仍待审。没有数据库、代码迁移或运行验证。

用户明确Source/Channel为稳定主数据，到点建立频道采集任务，一次可处理多篇；不论单任务还是父任务加逐篇明细，完成后所有任务/明细都删除。此前AI将“运行记录持久化”解释为永久采集统计及历史，偏离用户原意，本次撤回，不归因为用户新增历史需求。

REQ-003保留编号，改正文义；撤回collection_runs/run_article_links。频道采集与既有音频任务共用pending_jobs，新增kind=channel_collect及仅供频道采集恢复的pending_job_items。到期创建任务与推进schedule.next_run_at同事务；逐篇正文/句子、TTS任务和明细检查点同事务。采集完毕交接后删除父任务和全部明细；未完成音频任务在同一表独立保留，发布成功即删。无永久任务关联或发布计数，不另建归档/队列。

恢复原意不取消必要的租约、重试、稳定来源去重或独立调用用量。失败未完成任务保留；来源不足允许少采，不重复文章补数。成功频道任务删除后的调度幂等由持久next_run_at和原子入队保护，不靠永久运行历史。

已同步需求/来源对照/术语/待办、ADR-0003/0015、架构及后台方案、数据模型/状态机/验证。历史intake保留原整理并在顶部标记纠正。逐表Lookup、Vocabulary、Translation和三模式初始进度示例见[数据示例](../design/data-examples.md)。没有擅自确认上一轮members和题组版本精简建议。

实现验证留后续：任务删后重复心跳、并发到期入队、三篇中途崩溃续作、最后一篇事务前后中断、父任务/明细全删、TTS独立完成删除、已处理来源不再抓取、无完成历史遗留。本轮不创建Issue、不执行RSS Spike、不提前finalize或commit。
