## 复习常量与转换

2026-11-16用户最新规则：只有round与due_at，不区分正式/短练，不存phase、is_retry或session。round是可回退的轮次进度，不是累计答对次数；答错最低保持0。

唯一REVIEW_STAGES定义：

| 答对后round | 下一次等待 |
|---|---|
| 1 | 1天 |
| 2 | 2天 |
| 3 | 4天 |
| 4 | 7天 |
| 5 | 15天 |
| 6 | 30天 |
| 7（终点） | NULL，已完成 |

初始round=0、due_at=NULL。数组定义所有间隔及终点，不另散落硬编码7/59天。now使用最终提交事务的DB UTC时间；一天按经过24小时计算仍属待审设计参数，显示设备本地时间。

| 当前条件 | 事件 | 写入 |
|---|---|---|
| 未开始或已到期、未完成 | correct | round+1，查所得轮次的等待；终点due_at=NULL，否则due_at=now+等待 |
| 未开始或已到期、未完成 | incorrect | round=max(0,round−1)，due_at=now+10分钟 |
| 任意 | technical failure / 未提交 / 未知结果尚未核对 | 不写错误成绩，不改变round/due_at；未知按原operationId核对 |
| 未来due或已完成 | 试图提交 | 拒绝，不改进度 |

例一：round2到期→答错降至1、等10分钟→答对升至2、再等2天。例二：round2到期→错至1→10分钟后再错至0→10分钟后答对至1、等1天。连续错误会逐轮回退，这是用户“再错再减”的直接含义，不能承诺连续错误后一次答对仍恢复原轮次。例三：初始0答错仍0、等10分钟→答对1、等1天；此前“0轮短练成功仍0再等1天”建议撤回，不再有未决分支。

每次只改当前mode。New需round=0且due_at=NULL；0轮有due已开始，不计new。Archived为三个round均到统一终点。页面展示nextRound=round+1，终点无下一轮，不显示Practice或isPractice。当前题面不显示固定批次总数。

每次下一题实时查询该mode到期与未开始词，到期先于新词；新收藏/刚到期词可加入下一次查询。无review_sessions/review_session_items、无cohort、无固定批次或恢复批次的承诺。关闭只退出页面并恢复原Vocabulary上下文；已保存结果保留，未知操作保留operationId核对。

返回题面只读当前词卡，不建题目或作答历史。提交复用通用operationId，先检查可答性并从数据库取答案，判定后短事务锁卡/进度重查存在性、实际答案和due条件，更新进度与receipt committed同事务。重复operation在24h可配置窗口内只确认已保存并重读进度，不重判/重写；不同operation竞争时先提交把due推到未来或完成，后者拒绝。超过窗口不自动重放旧答卷，不承诺旧题或原判定恢复。删除清词卡及其三模式进度，迟到请求不upsert复活，无业务版本。

Spell标准化：Unicode NFC、trim、折叠多余空白及不区分含义的大小写；按acceptedForms精确匹配，不使用宽泛编辑距离接纳错误词。同义词/不允许的屈折不自动通过。Speak依赖/权限/无效录音失败为技术错误，不当作答错。

## 调度、运行和未完成任务

频道 schedule 用 IANA 时区计算下一 local occurrence，持久化 UTC next_run_at；任务去重键包含 schedule ID、local date、local time、本次计划配置快照。DST 春季不存在时刻建议顺延至当天第一个有效时刻；秋季重复只取首次。多个不同 schedule 即便映射到同一 UTC 时刻仍各自触发；schedule 更新不回写已入队任务。调度短事务锁定到期schedule、插入pending_jobs(kind=channel_collect)并推进next_run_at，任一步失败一起回滚。任务完成删除后，后续心跳由已经推进的next_run_at判断，不靠永久运行历史去重。

漏调后优先恢复旧未完成任务，再从next_run_at扫描尚未入队的到期时点。建议每心跳最多新增每频道4个 occurrence，持续分批追赶，不静默跳过其余；运维长时间积压需查看日志/DB，不建额外后台。具体时点/篇数仍由用户接入前配置，不能默认全站16篇。

频道采集任务在同一pending_jobs表执行，pending_job_items保存选中的文章URL/稳定键及逐篇pending/saved/skipped检查点，不保存第二份正文。每篇成功时同事务写source_items、preparing文章/句子、唯一article_tts任务，并标记明细saved；重复来源键只核对既有文章/任务，不重复抓取生成，不把之前待重试文章计为本次新增。可重试失败保留未完成明细；来源不足或永久无效项按已接受的少发规则处理。全部采集工作结束并可靠交接音频任务时，同事务校验租约并删除频道任务和全部明细。没有collection_runs/run_article_links、succeeded历史行或永久发布计数。文章发布不依赖已删除的频道任务。

任务 `pending→running→waiting_retry / waiting_capacity / blocked`，频道采集完成交接、文章成功发布或例句/词头生成引用时，分别**删除对应任务及全部临时明细/检查点**，不写 done。失败/检查点均为未完成项。即时例句请求先原子创建/领取同一 pending_jobs 单飞条目并在请求内尝试，不等15分钟扫描；处理中重复点击返回202 + 操作状态。失败可由同一表被后续心跳恢复，绝不新增例句专用队列。

建议初值：单实例后台并发2、租约90秒/每30秒续约、单步外部超时不超过45秒，处理器约240秒进入收尾；最终数值受平台实际限制和 spike 结果约束。不得将多分钟调用硬塞进45秒；若候选步骤不能分块满足时限，则该候选不满足此配置。截止前保存 checkpoint 并退出，空队列立即返回。

领取短事务：`SKIP LOCKED` + 到期条件，fence 单调+1。续租、写 checkpoint、上传后绑定、最终发布均检查 job ID/fence/资源存在及实际输入内容；失租不能提交。单步上传使用包含资源ID/fence/分块ID的不可变键。外部调用不放在长 SQL 事务中。

退避建议：瞬时依赖失败以1/2/4/8/16分钟 + 有界抖动计算 retry_at，实际受15分钟唤醒节奏影响；连续5次后 blocked 仍保留，下一个频道批次最多优先重领一次，不无限占每个心跳。永久无效输入保持 blocked，修配置/正文后明确 requeue。交互 AI 单次最多一次瞬时重试、遵守总截止；语义无效允许一次修复尝试，两次都记 usage；失败保留旧内容。存储不足 waiting_capacity，不以紧循环删除新文章。

## 发布与清理

生成前原子容量预留→事务外分块生成/上传→验证正文覆盖与时间轴→短事务校验租约及资源存在后绑定完整资产、article.ready、删对应音频任务/检查点/释放预留。不存在run计数更新。若已 ready，直接返回已有结果，不因任务不存在重建。发布前崩溃从 checkpoint 续；上传后未入库的对象按生产者任务/租约/fence 核对，活跃对象不得误删。

每条新增音频路径先检查 observed + 未释放/待删计量 + reservations。占用达到95%触发按 first_created_at,id 升序清至实际低于90%；即便当前未到95%，预留/实际新对象会越过95%时也先执行清理。播放命中不改创建时间，禁止 LRU。超出预留先扩预留/清理再上传。staging/孤儿对象也计容量；新建不能绕过。

选中资产后按固定锁顺序 scope→资源→引用/资产→job/progress（涉及时）锁定，重查其当前引用。文章当前必需音频：同事务删文/句子/时间轴/访问/队列项/任务并失效fence、删除引用、资产转 retiring。例句：仅失效引用并转 retiring，例句保留。已替换的/无引用资产只删资产。提交后才删对象；失败在 media_assets 的 retiring 状态退避重试，不造第二张清理任务表。

物理删除返回成功也不能立即断言提供商容量已释放；更新应用物理字节并核对平台观测，不重复无限删正常文章。建议每次生成只做一个有界清理批（最多50资产），预算或计量仍不够就 waiting_capacity，后续继续。已有签名地址可能在有效期内可用，不承诺即时撤销下载；新请求不再授权已删文。个人解释/例句/卡/进度不参与空间淘汰。

## 用量与未知结果

每次外部调用前先持久 usage_attempt pending：若 DB 无法记账则不开始新的收费尝试，返回可重试依赖错误。调用后写 provider request ID、已知用量、结果、计价版本；失败/自动修复/回退也各自一行。返回 usage 未知时 NULL/status unknown，不计0。

调用成功后 DB 不可用：已写的 pending 表示结果未知，不显示“业务已保存”；恢复时先核查资源/操作提交与供应商回执，不能拿未知当未调用并免费重试。原始响应可能随进程丢失，无提供商查询能力时保持 unknown，需要重新生成则新 attempt 记账，承认可能重复收费。不把原始录音留给恢复使用。

业务提交与 usage 最终化在可行的同一事务，但不同模块仅通过 application 调用公开端口。文章/卡删除不级联 usage；保留最小关联 ID/环境/模型计量，不留被删词卡文本或原始作答。金额是带 price_version 的估算，供应商实收未知则不填；不增加费用看板或30美元停用规则。
