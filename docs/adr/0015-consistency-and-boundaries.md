## 背景

已选模块化单体、Drizzle、临时任务表和 Neon 对象存储。无状态函数可能并发、超时或在外部调用后退出，单用 TypeScript 类型或队列消费顺序不能保证业务一致性。

## 候选方案

| 方案 | 优点 | 代价 |
|---|---|---|
| 模块数据主人 + Postgres事务/应用服务重查 + 外部对象对账 | 在现有平台内维护业务不变量，无第二套队列 | 需设计事务校验、租约、预留和崩溃恢复 |
| 仅前端禁重复/进程内锁 | 实现少 | 多实例/重试/删除竞争仍会重复推进或复活 |
| 拆独立服务与分布式事务设施 | 可独立扩展 | 一人维护与当前规模缺少收益，增加运维/费用 |

## 决策

依 overview 的路由 → application → 模块服务/领域/仓储端口组织，依赖由装配入口注入。domain 无框架依赖，模块不直接写别人的表，dependency-cruiser 强制；Next/规范库的适配边界写入检查配置。

需要交互事务的任务领取、条件写入使用支持该语义的 Drizzle PostgreSQL 连接驱动；不能默认 Neon HTTP 单语句调用可以承载交互式事务。连接按 serverless 池化限制控制，网络/AI 调用不放长事务里。

- 2026-11-16采集澄清：到期建频道任务与推进next_run_at同事务，正文/TTS任务/临时逐篇检查点同事务，采集交接完成删除频道任务和全部明细，不保留永久运行记录。文章与音频任务同事务；SKIP LOCKED、租约、fencing token 防重复工作覆盖；稳定来源键/固定正文保证任务删除后仍幂等。发布/绑定完整资产/删除任务同事务。
- 创建时先上传不可变版本对象，再条件提交 DB 引用；孤儿对象按租约/引用对账。删除文章音频时，先在一个 DB 事务内删除文章正文/句子/时间轴、当前资产引用及访问记录，并把仅含对象键/版本/大小的 media 资产元数据标为 retiring；不保留文章正文等待物理删除。提交后幂等删除对象，失败由资产清理状态重试；文章不存在后不再签发播放 URL，旧 worker 不能重建文章。例句音频删除事务仅失效音频引用、标记资产待删，保留例句及全部学习文本/进度，下次点击朗读按需生成。SQL/S3 不具备共同事务：保证业务删除同一提交生效，允许对象物理清理重试，不把逻辑删除当作配额立即释放；不新增第二套队列。
- 查词/词卡刷新先在事务外生成并语义校验，提交时核对身份、实际词义/当前例句及存在性，不设业务版本列。重复替换保留进度。删除词卡后旧回调必须查存在/实际输入，禁止 upsert 重建。
- 2026-11-16最终复习仅保留review_progress。实时取题不落库；从当前词卡取答案，短事务锁卡/进度检查可答条件后更新，与通用receipt committed同事务。重复operationId在有限窗口内不重写；技术故障不计错，删卡清进度，重新收藏新ID。没有持久题面/答卷/判定历史或业务版本。
- 查词上下文快照独立于被淘汰文章；解释缓存与收藏分别拥有快照。FIFO 清音频不得删个人学习文本或复习进度。

## 证据与后果

依据已接受产品不变量与 ADR-0003/0005/0006；实现语义见 [PostgreSQL 事务](https://www.postgresql.org/docs/current/tutorial-transactions.html)、[SELECT / SKIP LOCKED](https://www.postgresql.org/docs/current/sql-select.html)、[Drizzle Neon 驱动](https://orm.drizzle.team/docs/connect-neon)。尚无并发/崩溃测试结果。

获得明确恢复路径，代价是必要的事务校验与对账逻辑。scaffold 之后需在真实测试 DB 验证租约竞争、重复提交、删除期间迟到回调及对象上传后崩溃。模型调用可能因崩溃重复收费，幂等业务提交不等于外部供应商恰好调用一次。
