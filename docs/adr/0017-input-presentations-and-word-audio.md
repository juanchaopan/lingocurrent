# ADR-0017 输入方式展示与词头音频缓存

- 日期：2026-11-16
- 状态：已接受，2026-11-16用户确认Design；未实现
- 扩展：ADR-0005/0009/0010/0011/0015；不替换已确认的技术平台

同一Next.js应用/业务/数据支持鼠标紧凑分页表格与触控连续加载卡片，平板结合宽度与实际输入方式，允许布局选择。共享查询语义和播放器/复习领域状态，不维护两套独立应用。列表增加全量排序/过滤及精确计数，仍在PostgreSQL内实现；中文匹配不假称English FTS可分词。

词头与例句音频均为按需可重建缓存，缓存键含文本与引擎/音色/编码版本，复用单一pending_jobs机制与media容量预留。新增word_tts不增加第二队列。FIFO/95%/90%包含词头资产；淘汰词头/例句仅删音频引用，文字与进度保留。文章当前音频淘汰仍同事务删文章及访问，不受此扩展影响。

小站点图标建议source_icons.bytea，与音频存储生命周期分开；音频总duration_ms在生成时保存供详情复用，不给列表增加对象元数据请求；字数不持久化。正式RSS接入前仍需来源和全文条件核对。详细决策和证据见[修订设计](../design/input-and-density-revision.md)。

后果：桌面/触控分别优化交互，需要共享契约以防漂移；更多词头对象增加缓存再生成/请求用量，但不改变Free约束或个人学习文本保留。触控、后台跨文与真实资源开销仍需后续验证。
