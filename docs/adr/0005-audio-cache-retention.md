# ADR-0005 按对象创建时间淘汰文章与例句音频

- 状态：已接受
- 日期：2026-11-15
- 相关需求：REQ-004、REQ-005、REQ-010、REQ-014、REQ-015、REQ-020、REQ-028–REQ-031
- 替代：ADR-0004 的“仅文章音频”和按文章时间淘汰部分

## 背景

用户最新明确例句音频也放对象存储作为缓存，命中直接播放、未命中才生成；清理按 Blob 创建时间，最早对象可能是文章或例句，两者均可淘汰。保留已选 95%/90% 高低水位。Neon 与 Vercel Blob 的供应商比较另行决定。

## 候选方案

| 方案 | 优点 | 缺点 | 适合条件 |
|---|---|---|---|
| 音频对象 FIFO + 例句按需重建 | 实现用户要求，音频缓存可控 | 老的热门对象也可能淘汰，再次生成有成本 | 当前用户直接选择 |
| 按最近访问时间 LRU | 更可能保留热门音频 | 需更新访问记录，也不同于用户指定创建时间 | 当前不选 |
| 仅保留文章音频 | 存储对象类型简单 | 例句无法跨会话命中对象缓存 | 被本次要求替代 |

## 决策

文章及例句朗读音频进入同一受控缓存范围，按对象首次成功创建时间从早到晚清理，稳定 ID 处理并列。读缓存不续期、不修改创建时间；淘汰后重新生成视为新对象。本 ADR 确定生命周期规则，供应商后续由 ADR-0007 确认为 Neon Object Storage；尚未实际配置。

例句命中可用音频直接播放；缺失或已淘汰时，按例句内容版本、引擎/音色等配置重新生成并缓存。即时例句请求不等待 15 分钟轮询。生成合并/租约可复用同一临时任务机制，成功后删除任务；不增加第二套永久任务历史。

容量检查嵌入所有会新增音频的生成路径，沿用 95% 触发、清至低于 90%，上传前检查实际大小及并发预留。此后不能只在文章 TTS 任务检查而漏掉例句生成。

用户在最终架构审阅中直接确认：删除文章当前必需的音频时，必须同时删除对应文章，不能只清音频而留下文章等待重建；文章访问记录、正文、句子和时间轴一并删除，全部个人学习文本与进度保留。例句的规则不同：只删除音频及缓存引用，例句继续保存在表中，下次用户点击朗读时重新生成并缓存音频。未引用的临时/旧版本对象只清资产，不删除仍有完整当前音频的文章。此边界已获用户明确确认，不再仅是前后要求的推导。

模型权重、原始作答录音、数据库备份不进入此音频缓存。内容版本变化或主动刷新时使用新缓存键，不错误播放旧例句音频。

## 证据

用户各轮直接要求 FIFO 和例句音频缓存，最终审阅明确“删除音频的话，文章也同时删除”，例句仍留表、下次点朗读重新生成，并要求修改后 finalize architecture。供应商选择后续已由 ADR-0007 确认为 Neon；能力见 [对象存储比较](../architecture/object-storage-options.md)。尚无实际生成、缓存命中或淘汰测试结果。

## 后果

- 好处：重复播放可复用生成结果，缓存增长受控，个人学习文本和进度保持独立。
- 代价：重新生成可能消耗 CPU/API 和上传操作；容量清理不退还历史流量，例句也增加写入量。
- 重新考虑条件：免费出网/操作先耗尽、无法可靠释放空间，或 FIFO 导致大量重复生成；修改策略仍由用户决定，不自动改成 LRU。
