# ADR-0010 设计来源、Storybook 与验证

- 状态：已接受
- 日期：2026-11-15
- 相关需求：REQ-001、REQ-008–REQ-028、REQ-032、REQ-033

## 背景

没有既有设计稿；用户选择原生语义组件、自有样式及 Tailwind，要求由 AI 先出可见设计并确认。阅读选择、嵌套浮层及音频跨页行为需要可复现的验证。

## 候选方案

| 决策 | 已选 | 比较与代价 |
|---|---|---|
| 设计来源 | AI 令牌与关键界面稿，由用户确认 | 相比先等外部设计稿可推进，但需要一次具体视觉反馈 |
| 组件展示 | Storybook | 独立呈现正常/空/加载/失败/长内容；增加构建配置，不使用付费视觉平台 |
| 单元/组件 | Vitest + React Testing Library | 相比两套测试入口更统一；区分服务端、jsdom、浏览器环境 |
| 流程/视觉 | Playwright 流程 + 截图回归 | 比只有流程更容易发现排版变化；维护关键基准图 |

## 决策

四项均由用户明确接受。Design 阶段先交付令牌、阅读/浮层/词卡/复习关键稿，用户确认后用于实现；本阶段没有生成或声称验收了这些 UI 稿。

展示组件通过 props 独立渲染，stories 至少覆盖正常、空、加载、错误、超长文本；页面由 Playwright 覆盖。视觉基准使用与 CI 一致的固定浏览器/字体/操作系统环境，本地 Windows 截图不直接冒充 Linux 基准。

关键业务测试针对真实风险：复习幂等/并发、删除不复活、词义去重与缓存隔离、任务完成即删、FIFO 清理及个人数据保留。数据库集成用真实测试 Postgres/Neon 分支。模拟 AI 用于可重复测试，真实语音质量不能靠 mock 证明。

真实 iPhone/iPad/Android、桌面浏览器的选区、录音权限、后台/锁屏及跨文章衔接在 staging 测试；Playwright 设备模拟不代替真实手机音频证据。

## 证据

用户明确选择；[Storybook](https://storybook.js.org/docs)、[Playwright 视觉比较](https://playwright.dev/docs/test-snapshots)及规范库 visual-testing.md。尚无界面或测试结果。

## 后果

- 好处：视觉标准和行为验证可复现。
- 代价：自有语义组件必须维护焦点、键盘、层级与无障碍；截图须控制环境和动态内容。
- 重新考虑条件：实际维护成本超出收益，可调整覆盖数量，不能无证据取消关键业务验收。
